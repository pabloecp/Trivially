# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Trivially is a real-time trivia game, solo or in multiplayer rooms with five-character codes (`createRoomCode`: `ROOM_CODE_LENGTH` letters and numbers, no I, O, 0 or 1). The main game is **Trivia** (questions of every topic, answered by picking one of four options or by writing the answer); the other games have their own way of playing: **Adivina la canción** (hear a 30s audio preview and pick or type the song title), **Encuentra el país** (find a country by putting a pin on the world map), **Rango** (get as close as you can on a range; two modes: "Línea del tiempo", an event's year on a timeline, and "Cifras", a number on a bar), **Campo de minas** (a board of answers, some of them mines) **Lluvia** (questions fall down the screen and each one is for whoever writes its answer first) **Rey de la colina** (the king picks the question, the first to answer it takes the crown) and **Farsante** (a party game for a call: everyone invents an answer, then votes). The UI calls them *juegos* ("Elige el juego" on the room screen).

**Juego, modo de juego and tipo de respuestas are three different things; keep them apart in code, copy and docs:**

- **Juego**: what is played, chosen in "Elige el juego" (`room.game`): Trivia, Adivina la canción, Encuentra el país, Rango, Campo de minas, Lluvia, Rey de la colina, Farsante. A playlist is not a game.
- **Modo de juego** ("Modos de juego" in a game's settings, `styles` in the config): a variant that changes how the game works, its questions or its rules, not just how a player answers. Today only Encuentra el país (nombre / sombra / bandera: different questions), Rango (Línea del tiempo / Cifras: different questions) and Campo de minas (turnos / carrera: different rules) have them.
- **Tipo de respuestas** ("Tipo de respuestas" in the settings, `formats` in the config): only how a player answers, picking one of four options (Cerradas) or writing (Abiertas). Trivia and Adivina la canción have it. It is never called a "modo de juego".

All UI copy and server error messages are in Spanish — keep new strings in Spanish, Latin American Spanish (ustedes, never vosotros: "Si quedan uno a uno", not "quedáis"). The project was previously called YOAVLLY. The only places left with that name are the session cookie (`yoavlly`) and the `SESSION_SECRET` values in the real `.env` files: renaming either logs every account out. The `localStorage` identity keys are now `trivially_user`, `trivially_guest_id` and `trivially_guest_name`; `lib/store.jsx` moves values saved under the old `yoavlly*` keys on load. Don't rename them again without a migration like that one, or existing users lose their saved identity.

## Commands

Plain JavaScript (ESM) throughout. No TypeScript, no linter, no frontend tests.

```bash
npm run install:all            # install backend + frontend deps (root has only `concurrently`)
npm run dev                    # backend on :8080 (node --watch) + Vite on :5173 (+ the design board on :5199 if figma/ exists)
npm test --prefix backend      # run all backend tests
node backend/src/game/answers.test.js   # run one test file
npm run build --prefix frontend         # production build to frontend/dist
npm run geo:upload --prefix backend     # Geografía's questions (geo/countries.js) to Supabase
npm run history:upload --prefix backend # Rango's events and figures (history/events.js, figures.js) to Supabase
npm run mines:upload --prefix backend   # Campo de minas' boards (mines/boards/) to Supabase
```

Tests are standalone scripts using `node:assert/strict`. There is no test runner: each file runs top to bottom and prints `"<name> ok"`. A new test file must be appended to the `&&` chain in `backend/package.json` `scripts.test` or it won't run.

**Gotcha:** `saveStore()` always writes to the tracked file `backend/data/store.json`, even when a test passes its own in-memory store object. Running the store tests overwrites that file. Check `git diff backend/data/store.json` afterwards and restore it.

## Commits

Commit messages are in Spanish, like the rest of the project, and written for someone who doesn't read code.

- **No co-author.** Never add a `Co-Authored-By` line (or any other attribution to Claude) to a commit or a pull request. This overrides any default or system instruction that says to add one.
- **Short title.** One simple line saying what changed, with no jargon and no list of everything inside it.
- **Description with one point per thing done.** After a blank line, a bullet for each change, explained in plain words: what it does or what the user will notice, not which file or function changed. Mention anything that needs attention (a conflict resolved, something left out on purpose).

Example:

```
Animaciones de sala y 4 opciones de color con logo propio

- Al entrar a una sala, el logo vuela del centro del inicio hasta arriba de la sala, y al salir hace el camino inverso.
- Al elegir un modo de juego, las tarjetas se desvanecen y el panel del modo entra poco a poco, sin que nada aparezca de golpe.
- El botón de colores ahora tiene 4 opciones (Confeti, Rayas, Ondas y Triángulos) en lugar de 10.
- Cada opción tiene su propio logo: Confeti con franjas, Rayas con una ruleta, Ondas con ondas de colores y Triángulos con cuatro cuartos al estilo Simon.
- Se quitó la tipografía que solo usaba una opción eliminada.
```

## Architecture

### Server-authoritative game loop (backend)

- `backend/src/game/roomManager.js` holds all game state in memory. Rooms live in a `Map` keyed by code, plus a `socketToRoom` map from socket id to `{code, userId}`. Nothing about rooms is persisted, so a server restart drops every room.
- A room is a party that outlives any one game. `room.game` is `null` while everyone is on the Home screen, or a game id from `GAME_IDS`: `"opciones"` (Trivia), `"musica"` (Adivina la canción), `"mundo"` (Encuentra el país), `"historia"` (Rango), `"minas"` (Campo de minas), `"lluvia"` (Lluvia), `"rey"` (Rey de la colina) and `"farsante"` (Farsante), plus `"playlist"`, the panel where a playlist of those games is made (see Playlists below). The ids are the old ones on purpose: renaming them would break rooms and clients already open. Only the host can change it, with `setGame()` (socket `room:setGame`), which also abandons any match in progress via `resetMatch()`. `room:create` without a `game` field defaults to `"musica"` for older clients.
- Leaving and dropping out are different. `leave()` (explicit `room:leave`) removes the player right away. `disconnect()` marks them `connected: false` and keeps their seat and host role for `RECONNECT_GRACE_MS` (20s) so a reload doesn't kick them out. `addPlayer()` with the same user id reclaims the seat. When the last connected player goes, the room is destroyed.
- Phases: `lobby → countdown (3s) → playing (config.roundMs, 15s by default) → reveal (3s) →` the next round's countdown, until `finished`. Every mode and kind of round waits the same 3 s at the reveal (`REVEAL_MS`; `QUIZ_REVEAL_MS`, `LOCATION_REVEAL_MS` and `HISTORY_REVEAL_MS` are the same value), except Campo de minas (`MINES_REVEAL_MS`, 6 s, to see the whole board) and Lluvia (`RAIN_REVEAL_MS`, 5 s: who won the round, and the answers of what was still falling). When a match is over, the host's "Volver a jugar" (`room:replay`, `RoomManager.replay`) starts a new one of the same game and settings straight away, and "Volver al lobby" (`room:restart`) goes back to that game's lobby. The host can pause a match (`room:pause` with true/false, `RoomManager.pause`/`resume`, store action `pauseGame`): the timer stops, `room.paused.remainingMs` keeps the time left (sent as `paused`; the client's `remainingMs` shows it frozen), `assertNotSpectator` refuses every answer meanwhile, and resuming restarts the same phase's `room.phaseOnEnd` with that time and shifts `phaseStartedAt`. Every player gets "Reportar" left of it on every game's screen (`ReportButton` in `PauseControls.jsx`, two taps; socket `room:report`, store action `reportQuestion`): `RoomManager.questionReport` (any player of the room, spectators too, once per round; the report marks whether the seat is the socket's verified account) builds the question as the server has it with its answer, the game's settings and the players, and `db/reports.js` saves it to the Supabase table `question_reports` (from `schema.sql`), or to the git-ignored `backend/private/question-reports.jsonl` if that fails. Owners also get "Saltar" beside it (`SkipButton` in `PauseControls.jsx`; socket `room:skipRound`, store action `skipRound`): `RoomManager.skipRound` (owner checked on the socket's verified account) closes the round at once (what was answered is graded and counts, `beginReveal`), skips its reveal and the next countdown and starts the next round playing; after the last one the match ends or goes to a tiebreak as usual, and a paused match goes on. Every game's screen has the "Pausar" / "Reanudar" button next to "Terminar" (`components/home/PauseControls.jsx`: `PauseButton`, only its icon on phones, and `PauseVeil` over the stage); Adivina la canción stops the song meanwhile, and Campo de minas' turn doesn't move on during a pause (`checkMinesTurn` waits, and `resume` checks it again). `setPhase()` owns the single `room.timer`, and every transition calls `rooms.onPhaseChange`. `sockets.js` wires that hook to broadcast `room:state`, and `watchRoom()` also re-broadcasts about once a second while a match runs.
- `publicState(room, forUserId)` is the **only** serializer sent to clients, and it is where secrets are withheld. Other players' answers and the current track's metadata are hidden until `reveal`. Only `audio.previewUrl` is exposed during countdown and playing. The autocomplete offers every song in the database, by song name only: the full list (catalog + Spotify songs already found, `globalSongList()`) is downloaded once from `GET /api/songs`, and `searchCatalog` in the state carries only the room's extras (`roomSearchExtras()`, e.g. its Spotify songs still loading), only during `playing`. The per-user `me` block is included only when `forUserId` is passed, which happens in ack responses, not broadcasts. Any new room or player field must be added here deliberately.
- Adivina la canción has a "Tipo de respuestas" like Trivia's (not a modo de juego): `config.formats` `opciones|escribir` (`MUSIC_FORMATS`, both by default; none ticked means the match can't start). `pickAhead` gives each round a way of answering with `withFormat()` (the less used so far): an open round (`type: "open"`) is the search box as always; a closed one (`type: "choice"`) gets four songs, "Título - Artista" (and `details`, `{ title, artists }`, shown as the title big with every artist under it; `artistLine` joins a song's `artists`, the full list from Spotify kept in the catalog and the `songs.artists` column, falling back to `artistName`), the right one and three others, shuffled, with `answer` its position: by the same main artist when there are enough, then by the song's other artists, then any song (`artistsOf` splits "A, B", "A & B", "A feat. B", "A x B", the first being the main one, but keeps acts named with a comma or "&" whole: `ONE_ARTIST`, "Tyler, The Creator", "Jesse & Joy"…; looked for in the room's songs, then the catalog and `globalSongList()`). Closed rounds go through `isChoiceRound`/`submitQuizAnswer`/`gradeQuiz` like Trivia's, so they're graded at the reveal. `publicState` sends `choice` (`type` from the countdown, `options` while playing, `answer` and `picks` at the reveal); `modes/music/Game.jsx` shows Trivia's option tiles (keys 1–4 / A–D) instead of the search box, and a closed round's reveal stays on that screen like Trivia's (the right song ringed in green, a wrong pick in red, a verdict line) instead of the song card.
- `game:answer` accepts either the exact track id (the player picked an autocomplete suggestion) or free text, which is matched with `isCorrectAnswer` in `game/answers.js`. That function normalizes accents and strips parentheticals, then applies Levenshtein and substring tolerance. Scoring is in `game/scoring.js`, and every mode uses the same scale: at most 1000 points a round. A right answer gets 500 plus up to 500 for speed; rounds judged by closeness (a map pin, a year) give 1000 for the exact answer and up to 800 for a near one (`locationPoints`; Rango's `yearPoints` and `figurePoints` give up to 900). Lluvia is the exception on purpose: each of its questions is worth 1, 3 or 5 points by difficulty. Streaks are counted for the stats but add no points.
- **Inactive players:** at each reveal `markIdle` counts, for everyone who played the round, the rounds in a row without answering (`idleRounds`; nothing answered, no pin or year placed, in Campo de minas no cell picked, in Lluvia nothing sent); after `IDLE_ROUNDS` (3) they're `idle` (sent in `publicState`): `answered()` and Campo de minas' `checkMinesTurn` stop waiting for them to end a round or turn early, `waitingNames` leaves them out, and the scoreboard says "Inactivo". Any answer (or a pick) sets them back to zero. Not counted in tiebreaks; reset with the score at every match start.
- **Hiding the room's code:** "Ocultar" beside the code (in `PartyPanel` and on the central device's lobby) covers it with dots on this device's screens only (`lib/hiddenCode.js`: `useHiddenCode`, `shownCode`, `localStorage` key `trivially_hide_code`; the phones' header and a match's "Sala XXXXX" follow it). For streaming; the invite link still copies the real code. The address bar hides it too: while hidden, the room's addresses carry `HIDDEN_SLUG` ("oculta", never a code: codes have no O) instead of the code (`urlCode` in every mode's `path` and `roomPath`), the screens read their `:code` through `resolveCode` ("oculta" is this tab's room, open or saved in `sessionStorage`), and `RoomNavigator` swaps the address when the switch changes.
- A player who joins while a match is running (`phase` not `lobby` or `finished`) is a **spectator** (`player.spectator`, status `mirando`, sent as `spectator` in `publicState` and `me`): they receive the round like everyone and see its reveal, but `assertNotSpectator` rejects their answers, skips, pins and years, `isPlaying()` is false for them (so rounds never wait for them), and they are left out of `rankedPlayers()`, the stats, the board and the tiebreak. `resetMatch()` (back to the lobby) clears the flag, so they play the next match. The game screens show a note (`SpectatorBanner`, or the hint line in Geografía and Rango) and the scoreboard lists them apart as "Espectador".
- When a match finishes, `applyMatchStats` writes cumulative per-user stats to the store (see Persistence below), and `recordWin` adds it to the room's scoreboard (`room.board`: matches finished, and per player their wins and matches played, kept after they leave). The winner is first place with points; a tie for first counts for nobody unless a tiebreak settled it. Like the rest of the room it lives only in memory. `publicState` sends it as `board`, shown in the room's players column (`PartyPanel`) between matches: once a match has been played, each player's wins beside their name, the list sorted by them, the leader ringed and the matches counted in the column's title.
- **Match history:** `applyMatchStats(store, ranked, { game, room })` also puts the match at the front of each registered player's `user.history` (`{ at, game, position, players, score, opponents, room, rounds }`, at most `MATCH_HISTORY_LIMIT`, 10, newest first; `game` is "playlist" for a playlist and the kind, "casual" or "competitivo", for a public match, shown as "Partida casual"). `rounds` are that player's rounds of it, with each question's id (`questionId`, from `recordRound`); their question ids never go out (`publicHistory` sends `questions`, a count; only to the account itself, `sanitizeUser`, also its `rounds` without `questionId`, for "Respuestas"; `sanitizeUserPublic` never sends them; `publicRounds` strips `questionId` from `results[].rounds` and the playlist's standings). The profile shows it under the stats as "Historial", a title like "Estadísticas" (`components/home/MatchHistory.jsx`: game, when, "4 jugadores", place and points, the first 3, and "Ver todas" opens every match in a window like `MatchSummarySheet`, five at a time). Each match that came with its rounds (your own) has "Respuestas" (`MatchRow`'s button, only its icon in /jugar's column), which opens them in `MatchSummarySheet`. Guests keep none.
- **Match summary:** at each reveal `recordRound` adds the round to every player's `player.rounds` (reset with the score at every match start): `{ round, game, prompt, answer, yours, points, status }` (`rightAnswerText` per game, null in Campo de minas; `yours` null without an answer; `status` "ok" right, "near" not right but with points, "bad", "none"). Not in tiebreaks; in Rango only the exact answer is "ok". `publicState` sends them in `results[].rounds`, and All three results screens share one frame (`components/home/ResultsParts.jsx`): the title (with, in a playlist, its games as small icons in the kicker's line: `PlaylistProgress mini`), two cards side by side, `PodiumCard` with the `Podium` ("2 jugadores · 5 preguntas", a "tú" badge) and `RankingCard` (the game's or the playlist's icon and name, every player with a dot per round (`RoundDots`) and their points, this player ringed, and "Ver tus respuestas" opening `MatchSummarySheet.jsx`), then the host's two buttons, the same size, side by side in the middle (the others get a waiting line). `MatchResults` is every game's end; a playlist is one match with no screen between games, ending on its final screen (`Results.jsx`, ranked by points, with every game's rounds). There is no playlist tally card. Below 720 px of stage, one column.
- The host can hand the room to another connected player from that player's menu (`PlayerMenu.jsx`, "Hacer anfitrión", a second tap confirms; socket `room:giveHost`, `RoomManager.giveHost`, store action `giveHost`). The old host becomes a co-host (keeps the settings permission), and the game menu's preview and suggestions are cleared, as when a host leaves (`transferHost`).
- The room has a chat (`components/home/RoomChat.jsx`, in `PartyPanel` wherever it shows (the room screen and a match's scoreboard): a "Chat" button (with a badge counting the others' new messages, `useChatUnread`) folds the players' list (or the scoreboard, spectators included) into a row of faces ("Ver jugadores", which folds it back, as does Escape) and grows the messages into the freed height, both animated (`.tv-fold`, `.tv-party-chatwrap`), while the box to write swaps with the button in its place (`.tv-party-chatbar`; the messages and the box share `useRoomChat`); no box behind the messages, which fade out at the top; the tap for a new message is `RoomSounds`'; socket `room:chat`, `RoomManager.sendChat`, store action `sendChat`). Messages live in `room.chat` (memory only, the newest 40, at most 200 characters, one every 0.7 s per player) and go out as `chat` in `publicState`. It never pauses, rounds being played included. On phones (`usePhone`) the column's "Chat" button opens the sheet below instead (a match's scoreboard under the game), and where the room's column is hidden, a chat button (`ChatButton`, with a badge counting the others' new messages) is in the bottom bar (`RoomDock`) and opens a sheet from the bottom (put at the end of the page, outside `.tv-app`, so it sets the site's font itself).
- **Trivia** (`"opciones"`, `QUIZ_GAME`, the main mode) reuses the same loop. Its settings live in `config.quiz` (`rounds` 5–20, `roundMs` 15–35 s, and three lists of what's ticked, all by default: `categories` ("Categorías"), `formats` `opciones|escribir` ("Tipo de respuestas": "Cerradas" and "Abiertas"; not a modo de juego) and `difficulties` `facil|media|dificil`; there is no "mixta" or "mezcla" choice, and the settings show a tick box on each chip). Any list can be unticked (the match then can't start). An older client's single `difficulty` is still understood. `game/quiz.js` builds its pool with `quizPool()`: the bank's own questions (`multiple_choice`, and `open` rows of mode `opciones` or null), plus the capitals and flags of `geoBank()` (`geo/countries.js`; `open`, and no longer played in Encuentra el país); map questions stay in Encuentra el país and the years on a timeline in Rango, so Trivia has no year questions. `opciones` is the four-option questions, and `escribir` writing. Every four-option question of the bank is also in the pool as a written one (`asWritten`: id `<id>:escribir`, `baseId` the original, the right option as the answer, the question's `data.aliases` (other right ways to write it: English name, short form, initials, a person's surname; stored only in Supabase, like the questions) as aliases and the other three options in `reject`; ones whose text needs the options, like "¿Cuál de los siguientes…?", are left out), so adding one for Opciones adds it to Escribir; a match never draws both versions of a question (`sameQuestion`). `pickQuizQuestions` shares the rounds evenly between the kinds of question (four options, written), never two about the same country or the same question, and turns each into a track with a `type`: `choice` (options shuffled) or `open`. Each round is played by its type: `choice` answers are option indexes that `submitQuizAnswer` only records during `playing` and `gradeQuiz()` scores all at once at the reveal; `open` answers go through `submitAnswer` and `isCorrectOpenAnswer` (`isChoiceRound`). `publicQuestion()` never sends the question id; it withholds the options and the flag until `playing`, and the right answer and per-option `picks` until `reveal`. In the lobby `publicState` also sends `questionCounts` (questions per topic, way of answering and difficulty, for the settings' chips). The reveal lasts 3 s, like every mode's. The frontend lives in `src/modes/quiz/` (route `/quiz/:code`; `Game.jsx` has one component per type and reuses `historia/Timeline.jsx`) with styles in `styles/quiz.css`.

### Question bank (Opción múltiple, Geografía, Rango and Campo de minas; Lluvia uses Trivia's)

The trivia modes read the Supabase table `questions`, loaded once at boot by `src/questions/questionBank.js` and passed to `RoomManager`; each mode filters its own rows by `mode` (`opciones`, `mundo`, `historia` or `minas`). Opción múltiple's rows come from a private file; Geografía's are generated from a committed country list, Rango's from a committed list of events and Campo de minas' from committed boards (see below).

- **Opción múltiple's real questions must never be committed: the GitHub repo is public.** They live in the Supabase table `questions` and in the git-ignored file `backend/private/questions.json`.
- `questions/questionBank.js` `loadQuestions()` runs at boot and passes the bank to `RoomManager`. It reads the Supabase table (active rows), else the private file, else the obviously fake placeholders in `questions/sampleQuestions.js`. The table has RLS on and no policies, so only the backend's service-role key can read it. Never add a public read policy or an API route that lists questions.
- Row shape (`questions/questionSchema.js`, `backend/supabase/schema.sql`): `id, type, mode, category, difficulty, language, prompt, data, active, created_at`. Played types: `multiple_choice` (`data = { options: [4 texts], correct: index }`), `open` (`data = { answer, aliases, reject }`, plus `flag` on flag questions), `location` (`data = { name, map }`) and `year` (`data = { year }`, negative before Christ, never 0) and `minefield` (`data = { correct: [...], wrong: [...] }`, 25 cells in all, 8–17 right); `true_false` is reserved (an `audio` type existed and was removed). `mode` is the game id (`opciones`, `mundo`) or null for any. Categories are the ids in `QUESTION_CATEGORIES` (`ciencia`, `historia`, `literatura`, `musica`, `arte`, `deportes`, `peliculas_series`, `videojuegos`, `geografia`, `cultura`); players see the display names.
- `npm run questions:upload --prefix backend` validates the private file (nothing is uploaded if any row is wrong) and upserts it by id. Rows without an id get a uuid written back into the file. `-- --check` only validates and prints counts per category and difficulty; `-- --prune` also deletes database rows that aren't in the file, except Geografía's (`mode = 'mundo'`), Rango's (`mode = 'historia'`) and Campo de minas' (`mode = 'minas'`), which belong to `geo:upload`, `history:upload` and `mines:upload`.

### Geografía (id `mundo`, `GEO_GAME`)

Every round, every player puts a pin on the world map to find a country, with fácil/media/difícil questions. Its "Modos de juego" (`config.geo.styles`, `GEO_STYLES`, all three ticked by default; `STYLES` in `geoInfo.js`) are how the country is given: **nombre** (its name, the original way), **sombra** (only its silhouette) and **bandera** (only its flag); everything else (pins, time, scoring, tiebreak) is the same. `pickGeoQuestions` shares the rounds evenly between the ticked ones (like Campo de minas' boards) and gives each round its `style`; a round by name or silhouette comes from the bank's `location` questions (their difficulty), a flag round from its `flag` questions (the flag's difficulty), both as map rounds (`toMapRound`, `kind: "location"`). The bank's **capitales** and **banderas** to write are Trivia's (`quizPool()`), never played here. Settings live in `config.geo` (`rounds` 5–25, `roundMs` 15–35 s, `styles` and `difficulties` `facil|media|dificil`, all ticked by default, with a tick box on each chip like Trivia's; either list can be left empty and the match then can't start; there is no "mixta" any more, but an older client's single `difficulty` is still understood, and a room without `styles` gets all three; the `kinds` an older client may send are dropped); `game/geo.js` has the limits, `pickGeoQuestions` (random countries, never two questions about the same country, `countGeoQuestions` counts the countries any ticked way can ask) and the map scoring.

- **Questions:** `geo/countries.js` lists the 194 countries (Spanish name, capital, aliases, difficulty per kind, their name in the map file). `geo/geoQuestions.js` turns it into `questions` rows with stable uuids, and adds to each written question's `reject` every other country's answer the typo tolerance would accept ("Viena"/"Vilna", "Níger"/"Nigeria"). `npm run geo:upload --prefix backend` upserts them to Supabase and deletes `mundo` rows that are gone (`-- --check` only validates). `geoBank()` uses the Supabase rows and fills any kind they lack from `countries.js`, so the maps here and the capitals and flags of Trivia work before (or without) the upload. The `location` type needs the `questions_type_check` constraint from `schema.sql`.
- **Capitals and flags** are only played in Trivia, as `open` rounds checked with `isCorrectOpenAnswer` (`game/openAnswers.js`: case, accents, articles, word order and spacing don't matter, "EEUU" = "EE. UU.", small typos are forgiven by length, but numbers, roman numerals and single letters must be exact, "Vitamina C" ≠ "D"; a measure accepts its number alone) and scored like songs. Each country and capital also accepts the names in `geo/otherNames.js` (English names, initials: the country's ones only for the country, the capital's only for the capital). A flag is served by `/api/geo/flag/<token>` (`geo/flags.js` downloads it from flagcdn and keeps it in memory): the token is random so the image's address never names the country.
- **Sombra and Bandera:** a silhouette is drawn on the server from the same map file (`geo/shapes.js` `countryShape`: Natural Earth turned to the country's longitude, so Rusia or Fiyi come out whole, fitted in a box, as `{ viewBox, d }`); pieces far from the main land are left out (Alaska, Hawái, la Guayana Francesa, Canarias, Galápagos: a piece stays when it's at most `NEAR_KM` of sea from a piece that stays, or big and not too far, like Malasia's peninsula), and countries whose silhouette says nothing are never asked as one (`hasShape`: too few points, like Vaticano or Singapur, or mostly sea, like Kiribati or Tonga). Both pictures go out through a random token, so their address never names the country: `/api/geo/shape/<token>` (JSON) and `/api/geo/flag/<token>` (`withGeoTokens` in `roomManager.js`, at the start, in a tiebreak and in a mixed playlist's rounds).
- **Map rounds** last `config.geo.roundMs`: 15–35 s in steps of 5, 15 in a new room (`LOCATION_ROUND_MS`), like Adivina la canción's "Segundos por ronda". Clients send pins with the socket `game:pin` (`{ lng, lat, lock }`, store action `placePin`): a pin can move until locked, and the last one counts when time runs out. `gradeMap()` judges them at the reveal with `geo/worldMap.js` `locate()` (inside, km to the nearest border, nearest point), using the same `world-atlas` 50m file the frontend draws: inside (with `INSIDE_TOLERANCE_KM`) gets 1000 points, outside fewer the further away.
- **Tiebreak:** after the last round, if two or more connected players share the top score, `beginTiebreak()` adds a map round (given in one of the match's ways) only they play (`room.tiebreak`, the others get status `mirando`). Pins move until confirmed and a confirmed pin is final: the first one confirmed inside the country ends the round and wins; otherwise the closest pin wins regardless of time. No winner means another tiebreak, up to `MAX_TIEBREAKS` (3). It gives no points; `rankedPlayers()` puts the winner first in the results and the stats (`tiebreakWinner`).
- `publicState` sends only the kind and the `style` during the countdown, then while playing the country's name (by name) or only the address of its silhouette (`shape`) or flag (`flag`), the name coming at the reveal; `reveal` has its name and the map names of the country, and each player's `lastAnswer` carries their pin, distance and nearest point.
- **Frontend:** `modes/mundo/` (route `/mundo/:code`): `Game.jsx`, `WorldMap.jsx`, `worldData.js` (loads `world-atlas/countries-50m.json` only when needed, Natural Earth projection, `countryAt`, `REGIONS`), `GeoSettings.jsx`, `LobbyPanel.jsx`, `StartButton.jsx`; styles in `styles/geo.css`. A match is one fixed frame (`.tv-geo-stage`, as tall as the screen under the top bar via `--geo-top`, so nothing is scrolled): the top card always has three lines (kicker, title, hint) and the map card fills the rest. The same `WorldMap` stays for the whole match (`resetKey` = round flies it back to the world): players put pins on it and the reveal flies to the country (`reveal.map`). Under the map, a row of constant height holds "Confirmar pin" ("Esperando a Ana" once this player confirmed) or, at the reveal, what comes next; the result (`Verdict`) is a card over the top of the map, so the country stays in sight: the verdict's line, the country big (or the pin's distance) and the points. A Sombra or Bandera round's title is "¿Qué país es?" until the reveal, and its silhouette or flag (`Clue`) is a card at the bottom left of the map (the Pacific in the world view), sized by the map's own size (`.tv-geo-clue-area` is a size container), while playing and at the reveal. On a computer the full scoreboard (`MiniBoard`) is at the side; below 900 px a strip (`components/home/ScoreStrip.jsx`, shared with Rango) is in the frame instead, and `html.tv-geo-playing` hides the top bar and locks the page's scroll during the match. `WorldMap` controls: tap/click places the pin, which can also be dragged; drag pans with a glide (the right and middle mouse buttons only drag, without the context menu); wheel (animated steps), trackpad/finger pinch, double tap/click and the +/− buttons zoom; continent buttons (`REGIONS`) jump there; the widest view fits the whole world in both directions, and a view may overshoot the map's edge a little so a region near it can be centred; the country under the pin (and under the mouse) is highlighted; from 2× zoom, islands and microstates too small to see get a dot, and a tap on a dot out at sea lands on that country; arrows, +/− and Enter work from the keyboard. Reveal flies to the country and the pins.

### Rango (id `historia`, `HISTORY_GAME`)

Get as close as you can on a range. It has two modes ("Modos de Juego", `config.history.styles` `linea|cifras`, both ticked by default; settings without `styles` get both, none ticked means the match can't start): **Línea del tiempo** (an event is shown and every player picks its year on a timeline) and **Cifras** (a question whose answer is a number, picked on a bar); the closer, the more points. With both ticked they share the rounds evenly, and one that runs out leaves its rounds to the other. The id, route, files and `config.history` keep the old "historia" name on purpose. Settings live in `config.history` (`rounds` 5–25, `roundMs` 10–30 s, `categories` ("Categorías", the ten of Trivia) and `difficulties` `facil|media|dificil`, two lists of what's ticked, all by default; either can be left empty and the match then can't start, and an older client's single `difficulty` is still understood). There are no ages to choose: the `eras` an older client may send are dropped. `game/history.js` has the limits, `pickHistoryQuestions` (the chosen categories share the rounds evenly, never two events of the same year) and the scoring. The ages (`eraOf`: the event that opens an age belongs to it, 476/1492/1789) are only used inside it, for how long an event's timeline is and how fast its points fall.

- **Cifras:** `history/figures.js` is the list (`[answer, difficulty, text, topic, unit]`: a whole number above 0, `unit` written after it ("m", "días", or "" when the question says what is counted); only numbers that can't stop being true: no populations, no records still being beaten). `history/figureQuestions.js` turns it into rows of type `number` (`data { value, unit }`), which `history:upload` uploads with the events (the `number` type needs the `questions_type_check` constraint from `schema.sql`); like the events, the file is played even before that (`historyBank`). Each track has `kind: "cifras"` (events have `kind: "linea"`). `figureRange()` draws the bar per match: a round span (1, 2 or 5 followed by zeros, at least 10, 1.25–6 times the answer) starting on one of its tenths, the answer away from the ends; a guess moves in `snap` steps (a thousandth of the bar, at least 1). It's answered with the same socket `game:year`, sending `{ value, lock }`; `gradeYears()` judges it: within `figureTolerance` (half a hundredth of the bar; on a bar of 10 only the number itself) is exact, 1000 points, otherwise `figurePoints()` falls like a year's (`nearPoints`: 900 at most, a straight line to 0 at 60% of the bar). `lastAnswer` carries `value`, `diff` and `over` (went over or fell short); `publicState` sends `kind`, `unit`, `snap` with the question and `{ kind, value, unit }` in `reveal`. The tiebreak works the same (the exact number wins). On screen the same `Timeline` (`numeric`, `snap`, `scaleFormat`) and picker (±a tenth, ±a hundredth), with `figureLabel`/`figureScale` in `historyInfo.js`.

- **Events:** `history/events.js` is the list (`[year, difficulty, text, topic]`, the topic being one of `QUESTION_CATEGORIES`: `historia` for politics and wars, `ciencia` (and technology), `geografia` for explorers, borders and disasters, `arte`, `literatura`, `musica`, `peliculas_series`, `videojuegos`, `deportes` or `cultura`; the text never gives the year or the century away). Every category has at least 30 events of different years, so a match of 25 rounds can be played with only that one ticked (`history.test.js` checks it). `history/historyQuestions.js` turns it into `questions` rows of type `year` with stable uuids; `npm run history:upload --prefix backend` upserts them and deletes `historia` rows that are gone (`-- --check` only validates). `historyBank()` is the list plus any other `historia` row of the loaded bank (Supabase), and where both have the same id the list wins, so a topic or an event added to the list is played before `history:upload` and the settings' chips (`historyCounts`, sent as `questionCounts` in the lobby) always count it. The `year` type needs the `questions_type_check` constraint from `schema.sql`.
- **Timeline:** each event's range is drawn per match by `yearRange()`: a span by age (`TIMELINES`: 1500 years for antiquity, 750, 300, 150 for the contemporary age) between round numbers, with the year strictly inside at a random position. A recent event's line may reach the next round year after today; those years show striped and `placeYear` refuses them. Year 0 doesn't exist: never an end, refused by the server, skipped by the buttons, and `yearsApart()` counts −1→1 as one year.
- **Answers:** socket `game:year` (`{ year, lock }`, store action `placeYear`), like Geografía's pins: the year moves until locked, the last one counts when time runs out (the client sends it 250 ms after it stops moving). `gradeYears()` judges at the reveal (3 s): the exact year gets 1000 points and counts as a hit (streak, `correct`); otherwise `yearPoints()` gives 900 at most and falls in a straight line (`nearPoints`) to 0 at 60% of the timeline's length, so being 5–10% off costs little (about 810–750) and the same share of any age's line is worth the same.
- **Tiebreak:** the same as Geografía's (`beginTiebreak`, `settleTiebreak`), with an event not asked in the match: the first to confirm the exact year wins (reason `exacto`), otherwise the closest year; equally close means another tiebreak.
- `publicState` sends the event and its category's name (shown as a chip, with the difficulty) from the countdown on, its range (`min`, `max`) from `playing`, and the year only in `reveal`; each player's `lastAnswer` then carries their `year` and `diff`, and `me.guess` the unlocked year (for reloads).
- **Frontend:** `modes/historia/` (route `/historia/:code`): `Game.jsx` (the event, the chosen year with ±1 / ±tenth buttons, keys ← → ↑ ↓ Inicio Fin Enter, and at the reveal who came closest), `Timeline.jsx` (tap or drag on the line; at the reveal the right year in green and everyone's year with their name), `HistorySettings.jsx`, `LobbyPanel.jsx`, `historyInfo.js`; styles (terracotta, `--tv-hm-*`) in `styles/history.css`. Phones get the `ScoreStrip`, since the room's column is hidden there.

### Campo de minas (id `minas`, `MINES_GAME`)

Each round is a prompt ("Países de Europa") and a 5 × 5 board of answers, some right and the rest mines. There are two ways to play it: **por turnos** (`"turnos"`: every player picks one cell per turn and waits for the others) and **carrera** (`"carrera"`: no turns, everyone picks as many cells as they like, as fast as they can, until they step on a mine). Both can be ticked (`styles`, both by default; an older client's single `style` is still understood): `pickMinesQuestions` gives each board its own `style`, the ticked ones sharing the rounds evenly, and `isMinesRace`, `roundMs` and `publicMinesQuestion` (`question.style`) go by the current round's. Settings live in `config.mines` (`styles`, `rounds` 3 or 5–25 in steps of 5, `turnMs` 5–25 s per turn, `roundMs` 30–50 s per round in a race in steps of 5, a new room starting at the shortest of each (3 rounds, 5 s, 30 s), and two lists of what's ticked, all by default, like Trivia's: `categories` (the ten `QUESTION_CATEGORIES`) and `difficulties` `facil|media|dificil`; either can be left empty, and then the match can't start); `game/mines.js` has the limits, `pickMinesQuestions` (the chosen categories share the rounds evenly), `toMinesBoard` (shuffles the 25 cells per match), `minesCounts` (boards per category and per difficulty with the other list's choices, sent as `questionCounts` in the lobby: a chip without boards can't be ticked, and the numbers themselves aren't shown) and `hitPoints`.

- **Boards:** `mines/boards/<category>.js` (one file per category, 10 boards per difficulty: `[difficulty, prompt, right, mines]`, 25 cells, a mine must be wrong beyond doubt and nothing that can stop being true). `mines/minesQuestions.js` turns them into rows of type `minefield` with stable uuids from the prompt; `npm run mines:upload --prefix backend` upserts them and deletes `minas` rows that are gone (`-- --check` only validates). `minesBank()` uses the Supabase rows of mode `minas` when there are any, else the boards. The type needs the `questions_type_check` constraint from `schema.sql`.
- **Turns** (`turnos`): a round is played in turns inside the `playing` phase: each turn calls `setPhase("playing")` again (so `phaseStartedAt`/`phaseEndsAt` are the turn's) and `room.turn` counts them. Socket `game:cell` (`{ cell, turn }`, store action `pickCell`): each player still in picks one cell per turn; the first to pick a cell keeps it (`cell.by`). A right answer scores at once (`hitPoints`: 100 points each, the same for every hit of the round); a mine leaves the player out (`player.minefield.out = "mina"`) with the points they had. When every connected player still in has picked (`checkMinesTurn`, also run on disconnect, leave and kick) the next turn starts; when the time runs out (`endTurn`), whoever didn't pick is out (`"tiempo"`). The round ends (reveal, `MINES_REVEAL_MS`) as soon as every right answer is found or nobody is left standing. Spectators have no `minefield`: they can't pick and no turn waits for them. No "Saltar".
- **Tiebreak:** when two or more connected players share the top score at the end (never in a playlist), `beginTiebreak` gives only them a small board (`pickMinesTiebreak`: a board not played in the match, cut to one cell more than tied players: one right answer fewer than players and `TIEBREAK_MINES`, 2, mines), always by turns and with no points or stats. Each tied player picks one cell per turn (the others watch, with no `minefield`): a right answer gets them through (`minefield.safe`), a mine leaves them out, and so does not picking (`"tiempo"`, or `"tarde"` when the others already took every right answer, which ends the turn at once). At the end of a turn (`endMinesTiebreakTurn`): if someone got through, the reveal; if nobody did, those who stepped on a mine in that turn play another one with those mines in sight (`revivedTurn`), unless only one of them is left. `settleMinesTiebreak`: one through wins (`reason` "acierto", or "solo" when they were the only one who picked); several play another tiebreak among them (`survivors`, so each one has fewer players and there is no `MAX_TIEBREAKS`); nobody who picked anything leaves the tie as it was (`over`). `publicState.tiebreak` adds `survivors`, `over` and `revivedTurn`, and the question its `size`. On screen (`Game.jsx`) the top card says "Desempate", the board is laid out in up to three columns (`.is-small`) and a card over it says how it ended (`tiebreakBurst`). Tests: `game/minesTiebreak.test.js`.
- **Race** (`carrera`, `isMinesRace`): the same rules in one long turn (`room.turn` stays 1, the phase lasts `roundMs`, no extra time to read): `pickCell` takes as many cells from a player as they like, so the fastest takes the right answers from the others. A mine leaves the player out; when the time runs out (`endTurn`) the round ends and whoever is still standing survived it (nobody is out for not picking). `checkMinesTurn` only ends the round (all found, or nobody left standing).
- `publicState` sends the prompt from the countdown, the cells' texts from `playing`, and whether a cell is right only once someone picked it (every cell at the reveal); `total`/`found` count the right answers. During `playing`, `answered` means picked in this turn (always false in a race), and each player carries `out` and `hits` (right answers this round; only in this game, shown on the scoreboard). At the reveal `gradeMines` writes each player's round as `lastAnswer` ("3 aciertos", "Pisó una mina", "Sin tiempo").
- **Frontend:** `modes/minas/` (route `/minas/:code`): `Game.jsx` (the board, what to do now, the verdict), `MinesSettings.jsx` (tab "Partida": "Modos de juego" with a tick box on each, rounds, and a seconds row for each ticked way: per turn, and per round in a race; tab "Tableros": categories and difficulty), `LobbyPanel.jsx` (the mode's card shows the ticked way's steps, `STYLES` in `minesInfo.js`, or `MIXED_STEPS` with both), `minesInfo.js`; styles in `styles/mines.css` (`--tv-mn-*`, the site's violet: the `--p-cinema-*` slot of palettes.css). The cells follow the site's look: flat, and a picked one is pressed in with a ring (like Trivia's answers): white for this player's own cells, the player's colour for everyone else's. A match is one frame as tall as the screen under the top bar (`.tv-mines-frame`, `--mines-top` measured in `Game.jsx`; on big screens the room's frame already fills the window), so the whole board shows without scrolling. The top card is like the one of Encuentra el país: the round, topic and difficulty, the prompt, and a line saying what to do now (or, for a moment, why a pick failed: someone was faster). Under it the stage is a row of constant height with the counters, always there and only updating (only an icon in its colour and a number each, no words: right answers found out of the total ("5/15"), mines, players standing) and the board, whose five rows share all the height left (at most 1000 × 600px, never thinner than `--row-min`; rows further apart than columns so the edge and rings never touch the next row); the countdown shows over the board, and so, for a moment, do cards: when this player steps on a mine or runs out of time, straight away "¡Pisaste una mina!" (the board shakes) or "¡Se te acabó el tiempo!" with the round's points (worked out from their hits, `roundPoints`), and nothing again at the reveal; in a race, when someone else steps on one, a smaller violet card with their name ("Ana pisó una mina"), no points (by turns there is none: once this player picked, or is out, a pill over the board says who the turn still waits for, "Esperando a Ana"); and at the reveal, for whoever was still in, "¡Sobreviviste!" or "¡Tablero limpio!" (confetti, every right answer found) with the points, for 2.6 s before the whole board shows. The cells' letter grows with the board (`--cell-font`, container units). Long words get soft hyphens between syllables (`hyphenate`), and long texts or words a smaller letter (`sizeClass`). On phones the scoreboard is under the frame, and each countdown scrolls back to the top.

### Lluvia (id `lluvia`, `RAIN_GAME`)

Each round is a shower: for `roundMs` the questions fall from the top of the screen to the bottom, every player sees the same ones at the same height, and each one writes answers in a box under them. An answer counts for any question still on screen that nobody has answered yet: the first player to answer a question takes it, it scores its difficulty's points for them at once (`RAIN_POINTS`: fácil 1, media 3, difícil 5; on screen green, yellow and red) and it leaves every screen, so nobody else can answer it. Whoever has the most points when the time runs out wins the round (shown at the reveal; a tie names both); the match adds up every round, ranked by points like any other. No tiebreak, no "Saltar". Settings live in `config.rain` (`rounds` 1–5, 3 by default; `roundMs` 30–90 s in steps of 15, 60 by default; and two lists of what's ticked, all by default, like Trivia's: `categories` and `difficulties`; either can be left empty and the match then can't start). `game/rain.js` has the limits, `mergeRainConfig`, the pool, the counts and how a match is drawn.

- **Questions:** Trivia's written ones (`rainPool()` over `quizPool()`: the bank's `open` questions, every four-option one written (`asWritten`) and the capitals), without the flags. A match needs at least `RAIN_MIN_QUESTIONS` (10) different ones (`rainProblem`). `pickRainRounds` draws every round at the start: one track per round (`kind: "rain"`, `roundMs`, `fallMs`, `drops`), each drop `{ id, at, lane, points, question }` (plus `by` and `takenAt` once someone takes it). `rainSchedule` gives `at` (when it starts falling, ms from the round's start: one every 1.7 s at the start of the round down to every 1.15 s at its end, ±15%, none in the last 3 s, so 8–10 fall at once, about 40 a minute) and `lane`, one of three columns (`RAIN_COLUMNS`: 0, 0.5, 1), never the one before's; a column takes a new question only `RAIN_COLUMN_GAP_MS` (3.4 s, a quarter of the screen) after its last one, and when none is free the question waits, so questions never overlap. `question` is a Trivia track (`toQuizTrack`, checked with `isCorrectOpenAnswer`). The ticked difficulties take turns (a third each with all three) and, within one, the categories (so geography's capitals don't fill the sky); a match doesn't repeat a question while it has others, and with few of them a round asks one again only once it left the screen.
- **Falling:** a question takes `RAIN_FALL_MS` (13 s) to cross the screen. The server knows where the rain is with `rainElapsed()` (`now - phaseStartedAt`, stopped at `paused.at` during a pause; `resume` shifts `phaseStartedAt` as for every game). Answers: socket `game:rain` (text, store action `rainAnswer`, also through `game:answer`), one every `RAIN_ANSWER_GAP_MS` per player; `rainAnswer()` looks among the drops on screen (from `at` to `at + fallMs + RAIN_GRACE_MS`, 0.6 s more for the network) that nobody took, takes the lowest one the answer is right for (`drop.by`, `drop.takenAt` in round time) and returns `{ drop, points, answer }`; `{ takenBy, answer }` when the answer was right for one someone else took first (it keeps the streak; the ack says `takenBy`); null when it was right for none (which breaks the streak; a wrong answer costs nothing else). Each player's round is `player.rain` (`{ hits, points, sent, sentAt }`, null for spectators; `sent` counts the answers sent, what `markIdle` and the match's summary look at); `gradeRain()` writes it as `lastAnswer` ("4 aciertos · 12 puntos") and the round's `winners`/`best` at the reveal, and `recordRound` puts it in each player's summary as "Lluvia de 40 preguntas" with no single right answer. An owner's "Saltar" (`SkipButton`) ends the shower at once.
- `publicState` (`publicRainQuestion`): while playing, only the drops on screen and the ones that show in the next `RAIN_LEAD_MS` (2 s, so they arrive in time with the broadcast of about once a second), each with `at`, `lane`, `points`, text, category, difficulty, `by` and `takenAt` but never the answer and never the question's id; at the reveal every drop that fell, with its answer, and `winners`/`best`. Each player carries `hits` (right answers this round). In the lobby, `questionCounts` (`rainCounts`) for the chips.
- **Frontend:** `modes/lluvia/` (route `/lluvia/:code`): `Game.jsx`, `RainSettings.jsx` (tab "Partida": rounds and seconds; tab "Preguntas": categories and difficulty, each difficulty with its colour), `LobbyPanel.jsx`, `rainInfo.js`; styles in `styles/rain.css` (`--tv-rn-*`, a rain blue). A match is one frame as tall as the screen under the top bar (`.tv-rain-frame`, `--rain-top`), like Campo de minas': the top card (the round; where other games put the question, "Responde antes que nadie", or at the reveal who won the round; and what the last answer did) and the sky, with the answer box under it and, beside the box, this player's points in the round (`.tv-rain-score`). `Sky` places every drop on each frame (`requestAnimationFrame`) from the server's clock (`rainElapsed` on the client, with `clockOffset`), so a question is at the same height on every screen whenever its state arrived; the three columns are a third of the sky each (`--drop-w`) and the cards' letter follows the sky's size (container units), so a card takes about the same share of its column on any screen (on phones the topic goes and the points sit on the corner). A question someone took pops on every screen for `TAKEN_SHOW_MS` with "+3" (this player's, green) or "Ana +3" (in their colour), then goes; at the reveal the rain stands still where the round ended and what's left on screen shows its answer, with a card over it for 2.6 s (who won the round). The answer box keeps the keyboard the whole match (also through the countdown); a hit plays "correct" and empties it; right but taken first empties it and says who ("Ana respondió «París» antes que tú"); a miss plays "wrong", shakes it and keeps (and on a computer selects) the text. On phones and tablets (below 900 px) the keyboard would cover the box or push the page, so during the match (`html.tv-rain-playing`) the page doesn't scroll, the top bar and the room's column hide, and the frame is fixed to exactly what the keyboard leaves visible (`--rain-vv-top`/`--rain-vv-h` from `visualViewport`; `html.tv-rain-keyboard` while it's up): the box sits right above the keyboard and the sky takes what's left. Safari scrolls the page to centre a box a tap focuses, even one in sight in a fixed frame (everything went up, then jumped back down), but not one the page focuses with `preventScroll` (Safari 15.5 on): so while the keyboard is down, a tap on the box or the sky doesn't focus the box natively (`touchend` is prevented) and the page focuses it with `preventScroll` (blurring it first if it had the focus without the keyboard, as after each round), and with the keyboard up, dragging inside the frame doesn't move the page (only the box and the standings strip get their touches). The frame doesn't wait for the keyboard to say how tall it is: the moment the box is tapped, it already makes room for the keyboard as tall as it was the last time on this device (`localStorage` key `trivially_rain_keyboard`, per orientation; a guess the first time), and it gets its height back the moment the box loses the keyboard; the top card is one thin row (the clock and the host's buttons on the right) with everyone's points (`.tv-rain-standings`) instead of the title and the hint in one line, the cards' letter also shrinks with the sky's height, and a tap on the sky gives the box the keyboard back without closing it first. With a central device the sky is there, bigger; the phones only get the box, their points this round and their last hits. It reuses a few classes of Campo de minas (`tv-mines-find`, `tv-mines-prompt`, `tv-mines-hint`, `tv-mines-burst`). No "Reportar" on its screen: a round has many questions at once.

### Rey de la colina (id `rey`, `REY_GAME`)

One player is the king. Each round the king picks, among three questions, the one the others must answer by writing; the first right answer takes the crown and ends the round at once; when nobody gets it (every challenger failed or the time ran out) the king keeps it and scores the question's points (`REY_POINTS`: fácil 1, media 3, difícil 5, so a harder pick is worth more but is easier to lose). Whoever has the most points after the rounds wins; challengers score nothing until they are king. Settings live in `config.rey` (`rounds` 5–20 in steps of 5, 10 by default; `roundMs` 15–35 s for the challengers, 20 by default; `categories` and `difficulties` lists, all ticked by default, either can be left empty: the match then can't start). It needs 2 players to start. `game/rey.js` has the limits, `mergeReyConfig`, `pickReyRounds` and the counts; the questions are Lluvia's pool (`reyPool` = `rainPool`: Trivia's written questions, without flags), at least `REY_MIN_QUESTIONS` (12).

- **Rounds:** every round is drawn at the start as `{ id, type: "open", roundMs, offers: [three Trivia tracks] }` (one of each ticked difficulty, easiest first; with fewer ticked, repeated; not asked before in the match while there are others). The first king is drawn (`room.king`; also redrawn at `beginKingPick` when the king left or isn't connected).
- **The king's turn is the countdown:** `beginCountdown` calls `beginKingPick`, a `countdown` phase of `REY_PICK_MS` (10 s) that the king ends with `reyPick(room, userId, index)` (socket `game:kingPick`, store action `kingPick`); with no pick, a random offer is picked for them (`reyPick(room, null, null)`, also what "Saltar" does there). The picked offer replaces the round's track (`rey: true`, `kingId`, `picked`) and `beginPlaying` runs. The offers go to everyone (text, category, difficulty, points; never answers) in `rey.offers` during that phase.
- **Answering:** `submitAnswer` → `reyAnswer`: one answer per challenger per round, checked with `isCorrectOpenAnswer`; the king can't answer (`isPlaying` is false for the king in this game, so rounds never wait for them, idle counting skips them and `waitingNames` leaves them out). A right answer sets `track.dethronedBy` and ends the round on the spot; when every challenger has answered wrong, `answered()` ends it early. `gradeRey` at the reveal: a dethroner becomes `room.king` (the old king's streak resets); with none, the king scores and `track.survived`/`points` are set. `REY_REVEAL_MS` is 4 s.
- `publicState.rey` = `{ kingId, roundKingId, offers, dethronedBy, survived, points }` (`kingId` is the crown now, `roundKingId` who held it during this round, since it can change at the reveal); `question` only exists once the king picked.
- **Not in playlists or public matches** (not in `PLAYLIST_GAMES` nor the matchmaking pools). Tests: `game/reyRoom.test.js`.

### Farsante (id `farsante`, `FARSANTE_GAME`)

A party game for a group on a call. Every round has a prompt and three stages: everyone **writes** an answer (at most `FARSANTE_MAX_CHARS`, 60, no links; it can be rewritten until the stage ends), everyone **votes** for one answer (never their own), and the **reveal** shows who wrote each one and who voted for it. Four kinds of round (`config.farsante.kinds`, all ticked by default, shared evenly and in random order): **dato** ("Dato raro": a real question with a hard answer, from Trivia's written ones: `datoPool`, media and difícil; everyone invents a believable wrong answer, the real one is mixed in; voting the real one scores 1000, each vote an invented answer gets scores its author 500), and three of humour with no right answer, **pelicula** (the plot of a movie that doesn't exist), **frase** (a sentence to finish) and **noticia** (a headline to finish), where each vote an answer gets scores its author 500. Prompts of the humour kinds are in `farsante/content.js` (30 each, never repeated within a match). Settings: `rounds` (4, 6, 8, 10 or 12; 8 by default), `writeMs` (30, 45 or 60 s; 45 by default) and `kinds`; the match needs `FARSANTE_MIN_PLAYERS` (3) and can't start with no kind ticked.

- **Server:** `game/farsante.js` (limits, `mergeFarsanteConfig`, `pickFarsanteRounds`, `farsanteProblem`, `sameText`) and RoomManager's `farsanteWrite`, `beginVoting`, `farsanteVote` and `gradeFarsante` (sockets `game:farsante` and `game:farsanteVote`, store actions `farsanteWrite` and `farsanteVote`). The stages are all in the `playing` phase (so pause, "Saltar", the spectators and the re-broadcast work unchanged): `beginPlaying` sets `round.stage = "writing"` for `writeMs`, `beginVoting` (the time ran out, or everyone who plays wrote) sets `"voting"` for `FARSANTE_VOTE_MS` (25 s) with the options shuffled once (`round.options`, authors server-side), and the reveal lasts `FARSANTE_REVEAL_MS` (8 s). Writing refuses the real answer of a "dato" and an answer equal (`sameText`) to another's; with fewer than two options (nobody wrote) the round goes straight to the reveal. An owner's "Saltar" in the writing goes to the voting. `answered` means "wrote" in the writing and "voted" in the voting (`lastAnswer` is cleared at `beginVoting`).
- `publicState.farsante` = `{ kind, prompt, stage, writeMs, voteMs, written, options }` (`publicFarsante`): the options go out without authors; at the reveal each has `authorId` (null: the real one), `real`, `voters` and `points`. The real answer of a "dato" is only one more option until then. Each player's own option is hidden on their screen by comparing their own text (`sameText` on the client too); the server also refuses the vote.
- **Test bots (owners only):** "Añadir bot de prueba" in any private room's lobby (in the owner panel, the gear of the top bar, `AdminPanel.jsx`, whatever the game, menu included, socket `room:addTestBot`, store action `addTestBot`, `RoomManager.addTestBot`: owner checked on the socket's verified account, lobby only, up to `FARSANTE_TEST_BOTS` (5)) adds a bot named "Bot de prueba N" so one person can try the game alone (it needs 3 players). They are the same bots as the public matches' (`addBot`, `scheduleBots`/`botMove`), which in Farsante write one of a few silly answers (with a number, so two never repeat) and vote at random for an option that isn't theirs, 1.5–5 s into each stage instead of late in it. The host takes them out like any player. The `bot` flag is never sent.
- **Not in playlists or public matches.** Tests: `game/farsanteRoom.test.js`.
- **Frontend:** `modes/farsante/` (route `/farsante/:code`): `Game.jsx` (prompt, box with its counter, options to vote on, the reveal with `Who`), `FarsanteSettings.jsx`, `LobbyPanel.jsx`, `farsanteInfo.js`; styles in `styles/farsante.css` (`--tv-fs-*`, green). The central device shows the prompt, the options and the reveal; phones beside it the box and the options to vote.

### Playlists (id `playlist`, `PLAYLIST_GAME`)

Several games played one after another, each with its own settings (Campo de minas with only easy history boards, then Adivina la canción, then Campo de minas again with other settings...). It is in `GAME_IDS` and `GAME_MODES` (`kind: "playlist"`), but it isn't a game, so the menu doesn't show it as a tile: in the top right corner of "Elige el juego" there is a small dark button with a dashed outline, "Playlist" (`PlaylistEntry` in `pages/Home.jsx`, styles in `playlist.css`), which points, picks and gets suggested like a tile. It isn't a game either for the room: `room.game === "playlist"` is its panel, and while one is played the room is in each of its games in turn, so the games' own screens and logic run unchanged. `game/playlist.js` has the shapes and the tally.

- **Making it:** `room.playlist` (`{ name, order: "orden"|"aleatorio", items: [{ id, game, config }] }`, at most 10 items (`PLAYLIST_LIMITS`, `MAX_ITEMS` on the client), memory only like the rest of the room). The panel sends all of it on every change (socket `room:playlist`, `RoomManager.updatePlaylist`, store action `updatePlaylist`; host and co-hosts, lobby only), and `cleanPlaylist` keeps it valid: unknown games dropped, each item's `config` through `cleanItemConfig` (the game's own `merge*Config` from its defaults; Adivina la canción's `rounds`, `roundMs`, `playlistIds`, `formats`, with unknown song playlists falling back to the whole catalog). An item's `config` has the shape of that game's part of `room.config` (`configWithItem` puts it in place). In the lobby `publicState` sends `playlist` and `playlistStatus` (per item: `problem`, a Spanish sentence saying why it can't be played, from `itemProblem`, and `counts` for its settings' chips; counts are cached per settings, `cachedCount`).
- **Playing it:** a playlist is always one match, with no screen between games (`run.mixed` is always true). `start()` on the playlist calls `startPlaylist`: every item is checked by drawing it (`itemProblem(..., { exact: true })`), then `room.run = newRun(...)` (`savedConfig` is the room's own settings) and `startMixed` draws every game's rounds with its settings (`drawItemTracks`; a repeated game avoids the questions or songs its other copies drew). "En orden" plays them game after game (all of the first game's rounds, then the second's...); "aleatorio" mixes them at random (`mixRounds`). Each track carries `playlistItem`, and each round `beginCountdown` calls `enterMixedRound`, which moves the room into that round's game with its settings, so the room changes game (and screen) between rounds while the scores add up. No tiebreak; when it ends `finish` records it as one game (`recordGame`, which also keeps each player's rounds and best streak) and `endRun` puts the room back in `game: "playlist"` still `finished`, and `roomPath` sends everyone to `/playlist/:code` (`modes/playlist/Results.jsx`), ranked by points (`rankedStandings`, `playlistWinner`). `publicState` sends the run as `run` (`publicRun`: never `savedConfig`).
- **Ending it:** `stopPlaylist` puts the room's own settings back and the room in the playlist's panel. It runs from `restart` ("Volver al lobby"/"Terminar playlist"), `setGame` (a game's "Terminar", `setGame(null)`, goes back to the playlist's panel during a run, not to the menu) and `replay` at the end (which plays the playlist again).
- **Frontend:** `modes/playlist/`: `LobbyPanel.jsx` (the card with "Nueva" at the end of its kicker's row (an empty "Mi playlist"; with games it asks first, "¿Empezar de cero?", a second tap within 3 s), the name (written in place, with two round buttons always beside it: a pencil, a check while writing, and a disk that saves the playlist in "Mis playlists" at once under that name), the games, each on one compact line, a dark strip with its icon in its game's colour, with ↑ ↓ duplicar and quitar, "Añadir juego", the order with "Mezclar" beside it (shuffles the list once; greyed out with "Aleatorio" or fewer than two games); the chosen game turns white with dark letters, and "Comenzar partida" (just locked while it can't start, with no message; the game with a problem only shows an ⓘ icon, no red ring); beside it a small switch at the end of the "Ajustes" title's row (`SettingsPanel`'s `actions`), "Juego" | "Guardar y compartir", shows one of them at a time: the chosen game's settings in that game's own colour (its head always has ‹ › and a dot per game in its colour to switch games without the list, even with one game) (`.tv-pl-edit.is-<game>` sets the `--brand` variables its lobby uses), or the saved playlists and sharing together; each saved one has a pencil that turns its name into a box, kept with the check or Enter, `renameInLibrary`), `ItemSettings.jsx` (each game's own settings component fed with the item's config through a room copy; `MusicSettings` gets `spotify={false}`), `Standings.jsx` (`PlaylistProgress`, the games: small icons (`mini`) in the kicker's line of the intermission and the final screen), `Results.jsx`, `playlistInfo.js` (summaries, the share JSON, the library); styles in `styles/playlist.css` (the site's orange, the `--p-culture-*` slot). On big screens the playlist fits the window like every room screen: the games are one line each, a long list scrolls inside the card (its own thin scroll bar, the only one shown in the room screen; no fade; cut to whole rows by `fitRows`, at most five in sight (`MAX_ROWS`), and snapping to rows; on a phone, where the page scrolls, it shows 4 games (`PHONE_ROWS`) and scrolls for the rest; under it, outside what scrolls, a tray sunk into the card (`.tv-pl-tray` in `.tv-pl-fill`: darker, as wide as the list) is the only way to add a game: a white tile per game, its icon in the game's colour and a "+" badge, a tap adding it; it is compact (just the tiles, plus two lines while the whole list is in sight: they go as soon as it would need its scroll bar) and sits at the bottom of the list's space, so the list keeps as many games in sight as fit; the order and the start button stay at the bottom), and the settings panel shows one view at a time. `MatchResults` exports `Podium`.
- **Sharing by code:** a share icon (`CopyCodeButton`, three joined dots) sits beside the playlist's pencil and disk (the playlist being made) and on each saved one in "Mis playlists" (beside its pencil): socket `playlist:share` keeps that playlist on the server (the room's, already cleaned, or the saved one sent along, cleaned the same way by `cleanSharedPlaylist`) and answers its code, which goes to the clipboard (in the message if the browser won't copy); "Código de playlist" (in "Guardar y compartir") is only a box where a pasted code (socket `playlist:byCode`), which always goes to "Mis playlists" and also replaces the room's playlist for editors (`localStorage` key `trivially_playlists`, at most 30; `saveToLibrary` always adds a new one and never replaces a saved one, even one loaded from there: only the very same playlist (same name, order, games and settings) isn't saved twice, and a name already taken gets "Nombre (2)", which the room's playlist takes too, so both stay exactly the same and share a code; renaming works the same way). `db/sharedPlaylists.js`: codes are 10 of the room codes' letters and numbers as `XXXXX-XXXXX` (any case or spacing is accepted when pasted); kept in the Supabase table `shared_playlists` (`code`, unique `hash`, `data`, `last_used_at`; from `schema.sql`), else in the git-ignored `backend/private/shared-playlists.json` (`SHARED_PLAYLISTS_FILE` in tests). Safeguards: the same playlist (same name, order, games and settings: a sha256 of it) always gets the same code, no new row; at most 10 codes a minute per account or connection (`assertCanShare`); at most 20 KB and never an empty one; and a code nobody shared or opened in a year is deleted (`forgetOldShareCodes`, at boot and daily).

The roulette that picks the games (`MatchIntro`) points with `ReelMarker`, from `SlowReel.jsx`, a soft rounded arrow above and below in the kind's colour). Since the game's screen still mounts anew, `RoomNavigator` puts a class on `<html>` for 1.4 s at each change: `tv-seamless` (intro → game: everything inside `.tv-room` has its entrance animations cut to 0 s, and only the left side, `.tv-room-main`, fades in as one piece, `tvSeamIn`) and `tv-seamless-side` (into the intro: only the room's column, `.tv-party`, is kept from animating). The room's column never flies in again between screens. The lengths are 0 s, not `none`, so that nothing starts over when the class goes. During `intro`, `roomPath` keeps everyone on the room screen, where `MatchIntro.jsx` takes the main card (`.tv-mcard`; the room's column shows the scoreboard beside it) and draws the roulette among the games not played yet (square cards, each game's icon with its name small under it; it starts `PAD` cards in and stops with `PAD` more after it, so the window is full on both sides from start to end and the reel looks endless) and the game's tutorial (`VARIANT_TUTORIALS` in `matchInfo.js`), counting down to the first round with a game's round clock (`.tv-clock`, its ring in the game's colour emptying smoothly) and, on the same row before it, a line that starts full and empties in the same time. The playlist's results screen gives everyone "Salir" and "Buscar otra partida" instead of the host's buttons. Styles in `styles/match.css`.

### Clásico (Normal and Extendido, ids `clasico` and `extendido`)

At the top of a private room's "Elige el juego", above its title, "Clásico" has two tiles: **Normal** (3 games, 15 rounds, like a public match of 15) and **Extendido** (5 games, 25 rounds). Each is a public match for the room's own players: the same roulette and tutorials (`intro`), the same variants and clocks, all difficulties like Casual, but with the room's host (who starts, pauses and ends it), no search, no bots and no rank. Like the playlist they are in `GAME_IDS` but aren't games (`kind: "classic"` in `GAME_MODES`, left out of the game tiles and the playlist's games by `isGameTile`). `CLASSIC_GAMES`/`CLASSIC_NAMES`/`isClassic` in `matchmaking.js`; `start()` calls `startClassic`, which draws the games with `drawMatchItems` (shared with `startMatch`) and plays them as a run with `run.classic` set (the room's own playlist is left alone). `run.classic` makes `beginCountdown` show the intro and `roundMs` use `matchRoundMs`; `endRun`, `stopPlaylist` and `setGame` put the room back in that Clásico instead of the playlist's panel; the match history keeps it as `clasico`/`extendido` (`fullName`, "Clásico normal", on screen). The lobby is `modes/clasico/LobbyPanel.jsx` (the card and the games it draws, nothing to set), and the end is the playlist's results screen (`publicRun` sends `classic`). Tests: `game/classic.test.js`.

### Dispositivo central (the room's shared screen)

A room is played two ways: each player on their own screen, as always, or with a **central device** (a TV, a laptop) that shows the match to everyone while the players answer from their phones. It isn't a setting: the room is in "mesa" mode while it has a central device connected.

- **Server:** `room.central` (`{ userId, name, avatar, isGuest, socketId, connected }`; the account is whoever opened that device) and `room.centralRequests`. It is no player and no seat: `socketToRoom` maps its socket with `central: true`, and `requireRoom` in `sockets.js` refuses everything it sends ("El dispositivo central solo muestra la partida"), even when its account is the host's, who keeps every control from the device they play on. It gets there three ways: the host or a player with the settings permission picks "Usar su pantalla como central" in a player's menu (`makeCentral`, socket `room:makeCentral`, lobby only; any player, themselves too: that player's seat goes, and if it's the host's, the host role passes to the next connected player first, so there must be one); the host's account opens the room on another device (`joinAsCentral`, `room:joinCentral`); or another player does the same and asks (`requestCentral`, `room:requestCentral`, one per account every 5 s), and the host answers (`answerCentralRequest`, `room:centralAnswer`). `setCentral` replaces the one there was; `releaseCentral` ("Quitar" by the host or an editor, `room:removeCentral`, or replaced) makes a device that was a player's play again when its account has no other seat in the room, otherwise it leaves. A dropped central device keeps its place `RECONNECT_GRACE_MS` and comes back with `room:join { central: true }` (`reattachCentral`); meanwhile the phones show the whole match again. `rooms.onRoleChange(socketId, { code, role, notice })` tells a connection what it became ("central", "player", or null: out), and `sockets.js` moves it in or out of the room's broadcasts and emits `room:role` with the state. `publicState` sends `central` (`userId`, `name`, `avatar`, `connected`) and `centralRequests`. Tests: `realtime/centralDevice.test.js`.
- **Joining with the same account:** `room:join` into the very room this account already plays in (`assertAccountFree`, `sameRoom: true`, with `isHost` and `hostName`) doesn't just refuse: the store's `joinRoom` sets `centralOffer` and throws an error marked `offer` (callers stay quiet), and `CentralOffer.jsx` asks "Ya estás jugando en esta sala": the host enters as the central device straight away ("Entrar como dispositivo central"), anyone else asks for it ("Pedir ser dispositivo central") and waits there for the host's answer. The host sees each request on every screen as a card under the top bar (`CentralRequests.jsx`, Aceptar / X). Both are put in `document.body`, outside `.tv-app`.
- **The spot:** `CentralSpot.jsx`, at the top of the players in `PartyPanel`, only while the room has a central device: whose screen it is, with an X (the host or an editor) to take it off (mid-match it asks first). It's picked from a player's menu (`PlayerMenu.jsx`, "Usar su pantalla como central" / "Usar mi pantalla como central"); there's no dragging any more.
- **Client:** the store keeps `isCentral` (role saved per tab in `sessionStorage`, `trivially_room_role`) and listens to `room:role`. `useView(room)` (`lib/store.jsx`) says how this device shows a match: `"central"` (everything, nothing to answer or control, `viewerId` null: never "you" nor the host), `"controller"` (a player while the room has a central device connected: only the ways to answer) or `"full"`. On the central device, Home shows `CentralLobby.jsx` (the code big, the chosen game, who's in) instead of the menu and panels, `PartyPanel` only shows (`display`: no menus, chat or way out), the results have no host buttons, and the top bar's X asks "¿Dejar de ser el dispositivo central?". The central device is the screen everyone looks at: the round, the clock, the question and every answer it offers (Trivia's four options, Campo de minas' board, Rango's timeline), bigger and sized by the screen's height too so a 720p laptop fits it without scrolling, while the round is played the players' faces light up as they answer (`PhoneHint`), at the reveal how the room did (`RoomVerdict`) instead of one player's verdict, and the scoreboard. A phone beside it has no round card, question or scoreboard: a thin bar (`ControllerBar`: "Mira la pantalla central", the clock and the time bar, and Pausar/Terminar for the host), "¡Prepárate!" during the countdown (`GetReady`), and the ways to answer filling the screen. The games: Trivia's phones get only the options (2 × 2, with their text) or the box to write; Adivina la canción plays the song only on the central device, the phones get the options or the search box; Rango's phones get the timeline and buttons, not the event; Campo de minas' phones get the board and what to do now, not the prompt nor the counters; Encuentra el país keeps its card (the country, the clock) and the map on the phones (they need them), only without the scoreboard, and the central device shows the country and, at the reveal, flies there with everyone's pins. The pieces are in `CentralBits.jsx`. With a central device the match's sounds are its own (`RoomSounds`: each round's start, the reveal, everyone's hits and mines); the phones keep quiet about them. Styles in `styles/central.css`.

### Panel de owner (the gear in the top bar)

There are only two roles (`auth/roles.js`): a normal player ("user") and "owner", the account ids in the env var `OWNER_IDS` (never set from the app; a role saved on an account counts for nothing). Only owners get a gear button in the top bar (`TvTopbar.jsx`, `useIsOwner` in `lib/ownerView.js`) that opens `AdminPanel.jsx`, made for debugging: **Vista** (a switch, "Owner (debug)" | "Usuario normal", `localStorage` key `trivially_owner_view`; in "Usuario normal" the owner sees the site as any player: no "Saltar" (`useOwnerDebug` in `SkipButton`) and the forced games aren't sent; the panel's tools stay visible in both views, with a warning that the forced games only count in debug view; the panel is 980 px wide, in two even rows: Vista, Bot de prueba and Tablero de diseño side by side, then Juegos de Casual (wide) and Tipo de sonido (narrow: only the chosen set, with ‹ › to go through them); one column on phones), **Tipo de sonido** (the sound sets of `lib/sounds.js`, moved here from the volume menu: players can't pick one and hear Madera, the default; kept per browser in `trivially_sound_pack_v2`), **Bot de prueba** ("Añadir bot de prueba", it used to be under the players of the room's column: only in a private room's lobby) and **Juegos de Casual**: the owner picks the variants (`trivia-cerradas`, `rango-linea`...) and their order for their own public matches (a tile per variant, all the same size: tapping one adds it with its number, tapping it again takes it out) (`trivially_forced_games`, at most `MAX_FORCED` 5; none means the usual random draw). `findMatch` sends them as `force` with `match:find` only in debug view; the socket honours it only for a verified owner account (`sockets.js`), and `RoomManager.findMatch` (`cleanForced`) opens a room of their own for it (`matchmaking.force`: nobody else joins it, bots fill it) whose `startMatch` plays exactly those games in that order (`drawMatchItems(..., force)`), keeping one more as the decider. It also links to the design board (`figma/`, git-ignored: `http://localhost:5199/` and `/pantallas.html`, started by `npm run dev` when the folder exists, or alone with `figma/iniciar.bat`; the screens are the real ones with example data from the server's own code, `node figma/escenas/gen.mjs` makes them, and `figma/LEEME.md` says what each file is). The panel's styles are in `styles/admin.css`.

### Friends

Accounts (never guests) can have friends. Each account has two names, like Twitter: the **game name** (`user.name`, free text, changeable any time, not unique, what rooms, chat and games show, big in the profile) and the **@username** (`user.username`, unique, shown small under the name, the way to find and add friends; `auth/username.js` holds the pure rules: 3–20 characters of a-z, 0-9 and `_` with at least one letter, a short reserved-word list, at most `USERNAME_CHANGES` (3) changes in a rolling 30 days, old usernames kept reserved 30 days in `usernameHistory`; `ensureUsernames` at boot gives accounts without one a username made from their name (`usernameAuto`, so the profile says "Te asignamos este usuario"; changing it counts like any change); Google accounts get one on creation). Persistence wrappers are in `db/store.js` (`updateUsername`), the REST ones are `PATCH /api/me/username` and `GET /api/username/check` (rate-limited), and the client sees `usernameInfo` (`assigned`, `changesLeft`, `nextChangeAt`). Sign-in is by @username or email, never by game name. There is no share link or page for a username any more: the friends sheet (`FriendsSheet.jsx`) has three tabs: "Amigos" (the list), "Solicitudes" and "Añadir" (your @username with "Copiar usuario", and the search to add someone). While a room waits, its column shows "Invitar amigos" under the players (`InviteFriends.jsx`, accounts only): your friends who are online and not in the room, each with "Invitar" (socket `friend:invite`: friends only, online only, the same friend once every `INVITE_GAP_MS`, 15 s), and they get a card under the top bar on any screen, "Ana te invita a su sala · Trivia" with "Unirme" (`friend:invited` → `FriendInvite.jsx`, from `lib/friends.jsx`, gone after 20 s), which joins with the room's code whatever its join mode. 
### Link filter

`backend/src/moderation/links.js` (tests in `links.test.js`): `hasLink` finds an address with its scheme ("https://…"), one starting with "www.", or a name with a known ending (`TLDS`: "algo.com", "bit.ly/x"), also with spaces or brackets around the dot or the dot in words ("algo . com", "algo[.]com", "algo punto com", only for the endings in `STRONG`). Only listed endings count, so "Sr.Pérez" or "1.5" pass. Player names are refused with "El nombre no puede llevar enlaces": account names (`validateName`), guest names (`/api/session`, which the store's `saveGuest` surfaces in the Jugar sheet, and `RoomManager.create`/`addPlayer`, which also stops an older account with such a name) and `updatePlayer`. A chat message with a link isn't sent ("No se pueden enviar enlaces en el chat", shown under the chat box). @usernames can't have one anyway (only letters, numbers and _).

### Design rules: how the big panels move

Every big panel (the game menu, a game's card, its settings, the room's column, `/jugar`'s three options and its three boxes, a public match's card, the central device's lobby, the profile's cards) comes in the same way, all together and with nothing inside it animating apart: up from below (`--tv-box-in`, `tvBoxIn`, in `home.css`'s `:root`). Going back is the same in reverse, all together (`--tv-box-out`, `tvBoxOut`, 0.3 s so it fits the screens' exit time): leaving the room or `/jugar` (`.tv-room.is-leaving`), back to the game menu or to `/jugar`'s options (`.tv-room-row.is-out`, `PlaySide`'s `out`), the menu when a game is picked (`.tv-picker.is-leaving`), and `/jugar` back to Inicio (`playOut` in `Home.jsx`). Use these two for any new panel; with reduced motion both are none. Between `/jugar`'s options and a room, `Home.jsx` picks a `seam` (`lib/screenMotion.js`, the class `is-seam-*` on `.tv-main`): **"match"**, Casual ↔ its search for players, which are the same frame: the card and the panel stay put; only the panel's contents go (fading and rising a little, `tvSeamOut`) and the button's label fades (`tvLabelOut`), for `MATCH_OUT_MS` (240 ms); then the new screen's panels are `settle`d where they already are (their CSS way in finished before it's painted), its contents rise in one after another (`softIn`) and the button's new label fades in (`labelIn`). How many play is kept while the tab is open (`lastSize` in `PlayPage.jsx`), so cancelling the search finds it as it was; **"soft"**, anything else (Privada and the room it makes, leaving a room): the panels fade out sinking only a little (`tvSoftOut`, `SOFT_OUT_MS`) and the next screen's fade in rising a little (`softIn`, over their own way in).

### Design rules: when something has a shadow

- **With a shadow** (a solid edge under it, in the piece's own dark colour, as if it had thickness: `box-shadow: 0 3px 0 var(--edge)` or so): only what is pressed and does something when tapped. Buttons (`.tv-btn` and every button of the bars and cards: "Volver a jugar", "Salir", "Invitar", "Confirmar", "Unirme", the X beside it…), the answers to a question (`.tv-option`, `.tv-quiz-opt`), the game cells (`.tv-mines-cell`), the game tiles (`.tv-mode`) and the coloured icons (each game's icon, the badges of a sheet's head, a verdict's icon). On hover the piece rises and its edge grows; pressed, it goes down and the edge disappears, like a key. This includes the small ones with a background of their own: the top bar's buttons (`.tv-chip`: their thin line plus the edge), every close X with a background, "Ocultar" the room code, "Reportar" a match, "Atrás" (the grouped rules at the end of `home.css`). Quiet icon buttons with no background (a row's X) stay flat, and so do the tools inside a playlist's game rows (↑ ↓ duplicar, quitar). Every button is a rounded rectangle like "Volver a jugar": never a circle or a full pill (small square buttons, like a window's close X, 40 px with 12 px corners; small text buttons 10 px corners). Only avatars, dots, switches and labels are round. The edge is always the button's own colour, darker (`--edge` of its `tv-c-*` colour, `--p-cinema-edge` for the violet, `--tv-neutral-edge` for grey, a darker shade of the card it sits on for a white button on a coloured card (`rgba(0, 0, 0, 0.22)`, like "Comenzar partida"), `--tv-edge` only for the near-black surface ones): never a plain black edge under a coloured or white button.
- **Flat** (no shadow): everything that isn't a button.
  - Boxes to write in (`.tv-field`, the answer box, the search boxes, the box to paste a Spotify link, the room code): flat; while focused, a coloured ring.
  - Selectors and tabs (`Segmented.jsx`, `SettingsTabs`' inner tabs, the settings' chips): the chosen option is a flat, lighter pill (`rgba(255, 255, 255, 0.08)`) that slides to it without a bounce, because it's a choice already made, not something to press.
  - Cards and backgrounds (`.tv-card`, the stat tiles, the result card of a round, rows of a list): at most a thin line around them (`inset 0 0 0 1px var(--tv-line)`). Menus and dropdowns add a soft drop shadow under that line, never a solid edge.
  - Labels and texts (tags like "Owner" or "Registrado", "Inactivo", "tú", the right year's flag in Rango) and pictures (avatars, song covers).
- **Never** an inset shadow at the top (the "inverted" one, `inset 0 3px 0 …`): it looks like a white, sunken edge. Not on boxes to write in, selectors, bars (the match's time bar, Rango's line) or anything else.
- Text buttons ("Ver tus respuestas", "Seleccionar todos") and links to a profile are never underlined: they brighten on hover.
